# 公正な A2 の τ 再較正 — 設計記録（事前登録）

作成: 2026-11-10（複数シード拡大の実施前）。Gate 1 の A2 は τ を ℓ の較正値
（5.306877e-04）のまま Δ に流用したため、重みが単一トークンへ完全集中し
（ESS 比率 ≈ 0.0011、top_weight_share 1.0）、2 回とも 40 ステップを完走できなかった。
この較正はその交絡を取り除くためのもので、A2 arm の実行前にルールを固定する。

## 信号の定義（変更なし）

- A2 の信号は Gate 1 と同一: `Δ_t = log p_T(y_t) − log p_ref(y_t)`（温度スケール済み、
  サンプルトークン y_t での対数確率差。trainer の `sampled` モード）。
- 重みも同一: `w_t = exp(−Δ_t / τ)`。変えるのは τ の決め方だけである。

## なぜ ℓ のルール（中央値）をそのまま移せないか

ℓ_t ≥ 0 なので中央値は正のスケールになる。Δ_t は符号付きで、中央値が 0 以下に
なりうる。その場合 τ ≤ 0 は重みの向きを反転させるため τ として使えない。
したがって「中央値」という規則の字面ではなく、規則の意図（= 信号自身の分布から
スケールを決める）を Δ に合わせて読み替える必要がある。

## 採用するルール（凍結）

**推奨 τ = τ_ESS**: プールした Δ（32 問ロールアウトの全マスク位置）に対し、
`w = exp(−Δ/τ)` の ESS 比率 `(Σw)² / (n·Σw²)` が **0.479** になる τ。
0.479 は A1 の Gate 1 におけるマイクロバッチあたり ESS 比率の平均
（0.4793、gate1_results.md）である。

- 意味: 「公正さ」を「A1 と同じ実効学習量（重みの分散の度合い）」で定義する。
  A2 を潰した交絡は ESS の崩壊そのものなので、それを直接揃えるのが最も
  対象を絞った公平化である。信号（ℓ か Δ か）だけが A1 と A2 の違いになる。
- 近似性の留保: 0.479 は学習中のマイクロバッチ平均であり、較正で使うのは
  プール ESS である。両者は同じ量の別集計なので、一致は近似である。
  学習時の leak_stats（マイクロバッチ ESS の平均）で事後確認する:
  0.45〜0.55 帯に入れば公平化は成立とみなす。
- フォールバック: ESS の二分探索が退化した場合（Δ が全て等しい等）のみ
  `τ = median(|Δ|)` を使う。スクリプトはその場合も JSON に記録する。
- 参考値として `median(Δ)`（使えるのは > 0 の場合のみ）、`median(|Δ|)`、
  旧 τ での ESS も JSON に残すが、arm の τ には使わない。

## 手順

```bash
# README §4.1 と同じ 32 問ロールアウト（idx 0..31、同一シード）で Δ を測る。約8分。
cd opsd && ../.venv/bin/python calibrate_tau_delta.py && cd ..
# -> gate1_out/tau_calibration_delta.json（推奨 τ = recommended_tau）
# 公正な A2（追加シードの1番目、A0/A1 と同じ 43）:
SEED=43 bash scripts/run_arm.sh A2 sampled <recommended_tau> 40 2 4 steps 1
```

`calibrate_tau_delta.py` は `calibrate_tau.py` と同一のロールアウト
（同一問題・同一シード・同一モデル呼び出し）を使い、信号の計算だけを
trainer の `sampled` モードと同一の gather に替えている。したがって
ℓ の τ と Δ の τ は同一の分布基盤の上で比較可能である。

## 判定への扱い

- 公正な A2 が完走すれば、Gate 1 の判定式（A1 ≥ A0 + 2pt かつ A1 ≥ A2）に
  その値を入れて読む。完走しなかった場合も、leak_stats の ESS が帯に入って
  いたかどうかで「τ の問題か Δ 信号自体の問題か」を切り分けて記録する。
- この文書のルールは A2 arm の実行前に固定したものであり、結果を見て
  τ を選び直すことはしない。

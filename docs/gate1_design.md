# ゲート1 実験設計（事前登録）— アイデア3 Leakage 重み付け蒸留

- 作成: 2026-11-08（本実験の実行前に固定。以後の変更は変更履歴に理由つきで追記する）
- 前提: Step 0 ゲート通過（AVSD チェック）。実装詳細は impl_notes.md。
- 環境: PC bt-gaming / WSL `~/muse/idea3-opsd/`、OPSD 公式コード (commit ae7d251)、Qwen3-1.7B + LoRA (r64, 公式 1.7B スクリプト準拠)、RTX 3070 8GB。

## 条件（アーム）

全アーム同一: 初期モデル、データ順序とシード、ステップ数、生成・最適化設定。公式 1.7B 設定の β=0 (forward KL)、pointwise clip 0.05、fixed_teacher を全アームで保持する。

- **A0** 素の OPSD（公式設定そのまま）
- **A1** 提案法: トークン位置 t の損失項全体に w_t = exp(−ℓ_t/τ) を掛ける。
  ℓ_t = D_KL(p_T(·|prefix, z) ‖ p_ref(·|prefix))、p_ref = 凍結した初期モデルを**問題文のみ**で条件付け（特権なし）。p_ref は学習しない（AVSD チェックの条件1・2を死守：参照は凍結かつ特権なし、減衰は損失項全体）。
- **A2** アブレーション: 信号だけをサンプルトークンの Δ_t = log p_T(y_t|prefix,z) − log p_ref(y_t|prefix) に替えた版（w_t = exp(−|Δ_t|/τ) ではなく符号つき Δ_t を exp(−Δ_t/τ) で使用し、生成トークンで測る既存系 RLSD 型信号に寄せる）。A1 と A2 の差が「全語彙で測ること」の寄与を分離する。

## τ の決め方（事前固定）

学習前にキャリブレーションを行う: 初期モデルで 32 問のロールアウトを生成し、全位置の ℓ_t を計算して、その**中央値を τ** として全アーム・全ステップで凍結する。τ の実測値は実行ログに記録する（事後に動かさない）。

## 規模（2026-11-08 22:05 ユーザーが推奨規模を承認 — 確定）

- 学習: 120 ステップ、実効バッチ 8（per-device 1 × 勾配蓄積 8 を想定）、生成長 512、max_length 2048。学習データは公式データ先頭から（評価用と重ならない範囲で）使用。
- 理由: 公式が「100ステップ以内にピーク」と明記。500ステップ（約4k問）は数十時間級で非現実的。
- 実行方式: 40ステップ刻みのチェックポイント保存＋再開可能なチャンク実行（SSH セッション断に備える）。ログは PC `~/muse/idea3-opsd/logs/` に保存し、要所でローカルへ複写。

## 評価

- held-out: 学習に使わない 300 問（公式データから学習分と重複しない範囲で固定）。学習前（初期モデル）と各アーム学習後に greedy 生成で解かせ、\boxed{} の答え一致率（正規化した文字列一致）を測る。全アームで同一の評価集合・同一の生成設定。
- 副次指標: 評価ロールアウトにおける生徒エントロピーの推移（entropy overshoot の有無）、ℓ_t の分布統計。

## AVSD 死角の診断（学習と独立に実施）

- held-out 100 問について、単一の参照解から AVSD の3ビューを構成する（full = 参照解全文 / partial = 参照解の前半 / answer = 最終答のみ）。追加の解生成は不要（impl_notes の「別解が必要」という想定は、ビュー構成に関してはこの方法で回避できる）。
- 位置ごとのビュー不一致度 J_t = D_KL(q^A_t ‖ q̃^G_t)（算術プーリング教師と幾何プーリング教師の発散、AVSD の residual の分布版）と ℓ_t を計算する。
- 事前に固定する読み: **ℓ_t が上位25%の位置のうち、J_t が中央値以下の位置の割合が 50% 以上**なら、「AVSD のゲートは高 leakage 位置の過半を見逃す」と定量化できたことにする。

## 判定基準（事前登録、変更しない）

- ゲート1通過: held-out 正答率で **A1 ≥ A0 + 2pt かつ A1 ≥ A2**（1シード、小規模）。通過なら複数シードへ拡大を提案する。
- A1 ≤ A0 なら アイデア3 は終了。A1 > A0 だが A2 ≥ A1 なら「全語彙で測る」新規性は棄却し、結果を記録して次を検討する。
- 診断結果は合否と独立に報告する。

## 確定事項（2026-11-08 実行担当が確定・追記）

- 実効バッチ内訳: **per_device 2 × 勾配蓄積 4 = 8**（全アーム共通）。batch 1 実測 約35秒/系列に対し batch 2 は 約19秒/系列と高速で、VRAM ピークも 8GB 内に収まることをプローブで確認した。学習率は公式 1.7B スクリプトの **5e-6**、シードは全アーム **42**。
- 学習データ: 公式データのインデックス **[0, 960)** を使用（120ステップ × 実効バッチ8 = 960問ちょうど）。held-out 評価は **[960, 1260)** の300問、AVSD 診断は **[960, 1060)** の100問で確定（学習分と重複なし）。
- 評価: greedy 生成、生成長 **512**（学習の生成長と同一）、\boxed 抽出＋正規化一致（空白・$・\left/\right 等を除去した文字列一致、または数値として解釈可能な場合は数値一致）。math-verify は使わない。
- 実装上の数値安定化（定義の変更ではない）: 重み付き平均は全重みに共通する定数倍に不変なので、w は指数を最大値でシフトして計算する（log-sum-exp 型の安定化）。これがないと A2（符号つき Δ、小さい τ）で fp32 がオーバーフローする。A2 はこの τ では実効的に「最も負の Δ のトークンへの集中」に近づく（ESS で定量記録する）— これは事前登録した定義の帰結として記録する。
- メモリ最適化（値の変更ではない）: 教師・参照の forward は `logits_to_keep` で補完位置の logits のみ計算する（lm_head は位置ごとに独立なので値は同一）。検証: 同一条件プローブで step 1 の損失がパッチ前と完全一致（−0.0036）。`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` は WSL2 で "Failed to create GPU mapping" を起こしたため使わない。
- ℓ_t と Δ_t の分布は学習時と同じ温度（1.1）でスケールされた分布で計算する。p_ref の log-probs は fp32 で計算し bf16 で保持、信号計算時に fp32 へ戻す。

## 変更履歴

- 2026-11-08 23:09（ユーザー承認）: 生成バックエンドの vLLM 化を試行。**結果: 不採用**（以下）。 operative なバックエンドは当初の HF generate のまま変更なし。
  - 試行内容: TRL 0.26.0 対応の vLLM 0.11.2（torch 2.9.0、transformers 4.57.1 は維持）を別 venv `~/muse/gate1-env` に構築（gpu-env は無変更）。方式は colocate + sleep mode（server 方式は単一 8GB GPU でメモリ共存不可能なため不採用）。
  - エンジン単体では高速（128トークン生成 1.4秒 ≈ 91 tok/s、HF は 13〜31 tok/s）で、sleep→重み再ロード→生成の健全性も単体では確認できた。
  - しかし Trainer 内 colocate は次の壁に順に衝突し、最後の1つが解消できなかった: (1) 起動時空きメモリチェック（学習モデル駐車パッチで解消）、(2) util 0.5 では KV 不足（0.55 で解消）、(3) 初回ステップの wake 順序バグ（初回同期パッチで解消）、(4) **学習モデルと共存した状態での CuMem 再マップ失敗（"device not ready"、WSL2 の cuMem 脆弱性とみられ、enforce_eager 化でも解消せず）**。
  - 対策パッチ（patch_opsd4/5/6）はすべて `--use_vllm` 経路内のみで、HF 経路では不活性。復帰後の HF プローブで正常動作を再確認済み（損失 0.0035、exit 0）。
  - 詳細な実測は gate1_results.md の「vLLM 高速化の試行（不採用）」節。
- 2026-11-08 23:41 規模変更（ユーザー承認）: 学習ステップ数を 120 → **40ステップ/アーム** に削減する。理由: HF方式の実測が約250〜333秒/step（120ステップでは25〜33時間）と判明し、vLLM高速化もWSL2/8GBの共存問題で不採用となったため。判定基準（A1 ≥ A0 + 2pt かつ A1 ≥ A2）、τ、評価集合、その他全条件は不変。この削減により検出力は低下する（公式の「ピークは100ステップ以内」より手前で切る）ため、最終判定ではこの留保を明記する。

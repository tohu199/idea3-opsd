## 実装上の事故と最小修正（透明性のため記録）

- 提供された `patch_opsd_shuffle.py` はアンカー一致で適用できた（`fullkl_shuffle` 3ヒット）が、初回プローブ（ログ `logs/probeA1S_20261109_181938.log`、49 秒で落下）が `NameError: name 'self' is not defined` で落ちた。原因: `generalized_jsd_loss` は `@staticmethod` であり、パッチが挿入したシャッフルブロックがその中で `self._shuffle_gen` を参照していた（py_compile では検出できない実行時エラー）。
- 対策: `code/patch_opsd_shuffle_fix.py` による最小修正（3箇所）。`generalized_jsd_loss` に `shuffle_gen=None` 引数を追加し、ブロック内はそれを使い、呼び出し側（`compute_loss`、メソッド）から `self._shuffle_gen`（patch が `__init__` に作る、シード 20261109 の独立 Generator）を渡す。既存の `leak_stats_out` 引数渡しと同じパターン。**τ・シード・データ・判定基準・シャッフルの意味論（行内・マスク位置内のみ並べ替え、独立 RNG）は一切変更していない。**
- 修正後プローブは上記の通り合格し、本番・評価まで完走した。

## 判定基準への当てはめ（事前登録、実行前に固定）

- A1S ≥ 14.0% → 位置特異性は死: **該当しない**（A1S = 11.33%）
- A1S ≤ 12.7% かつ A1 − A1S ≥ 2pt → **位置情報が生存**: **該当する**（A1S = 11.33% ≤ 12.67%、A1 − A1S = **+3.67 pt**、正味 +11 問）
- 12.7% ＜ A1S ＜ 14.0% → 曖昧: 該当しない

**結論: 事前登録した読みでは「位置情報が生存」。** A1 と同じ重み分布・同じ分散度合いを持ちながら位置対応だけを壊した A1S は、step 0 水準を下回り（−1.33 pt）、素の OPSD（A0、11.67%）と1問差の水準まで落ちた。効いていたのは単なる減衰効果ではなく、leakage の位置情報だったことになる。

副次指標（エントロピー）: A1S の 0.3311 は A0 の 0.3488 に近く（差 0.018)、A1 の 0.2146 からは遠い（差 0.117)。設計の読み分け通り、**overshoot 抑制自体が位置特異的**だった（位置を壊すとエントロピーは A0 並みに膨らんだ）。主指標と副次指標が同じ方向を指した。

## 留保（結論の強さの限界）

1. **ノイズ**: n=300・1シードでは各正答率の二項標準誤差は約 ±1.9 pt で、A1 − A1S の +3.67 pt も独立仮定では約 1.3σ 程度。事前登録ルールへの当てはめ結果は上記の通りだが、これ単独を「証明」とは読まない。だからこそ次は複数シードである。
2. A1S と A0 の差（−0.33 pt）は1問差で、こちらは誤差の範囲内。「シャッフルすると A0 より悪くなる」とまでは主張しない。主張できるのは A1 との差と、step 0 水準以下に落ちたことである。
